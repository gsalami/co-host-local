## Codebase Patterns
- Auth system uses simple username/password from env vars (AUTH_USER, AUTH_PASSWORD)
- User sessions stored in SQLite sessions table (for WebSocket compatibility)
- Database: SQLite at ./data/cohost.db using better-sqlite3 and Drizzle ORM
- Session data structure: `sessionData.passport.user` contains user ID (not claims.sub)
- All routes access user via `req.user.id` (not `req.user.claims.sub`)
- Express.User type extended in server/types.d.ts to match DbUser from shared/models/auth
- WebSocket auth extracts userId from signed session cookies
- Login page at /login, Landing page at / (for unauthenticated users)

  - Created: migrations/0000_lazy_inhumans.sql (fresh SQLite migration)
  - Created: data/cohost.db (SQLite database file)
- **Learnings for future iterations:**
  - SQLite uses different type system: text (not varchar), integer with mode timestamp (not timestamp), integer autoincrement (not serial)
  - SQLite default functions differ: unixepoch() instead of CURRENT_TIMESTAMP, randomblob(16) for UUIDs instead of gen_random_uuid()
  - SQLite uses LIKE (case-insensitive by default) instead of PostgreSQL's ILIKE
  - better-sqlite3 requires explicit "foreign_keys = ON" pragma
  - drizzle-kit generate needs empty migrations folder when switching dialects (old snapshots cause version errors)
  - Data directory must exist before drizzle-kit migrate runs with SQLite
  - jsonb in PostgreSQL becomes text with mode: "json" in SQLite
  - Session storage (for WebSocket auth) still works with SQLite - no changes needed
  - Removed leftover credit system methods from storage.ts (they referenced deleted tables from ARCH-2)
